# [Programmers] 소수 만들기 (Level 1)

## 1. 문제 설명

주어진 숫자 배열 `nums`에서 서로 다른 3개의 숫자를 선택하여 더했을 때, 그 합이 **소수(Prime Number)**가 되는 경우의 수를 구하는 문제입니다. 중복된 숫자가 없으며, 선택하는 순서는 고려하지 않는 **조합(Combination)** 탐색이 핵심입니다.

---

## 2. 풀이 방식 (Brute Force & 효율적 소수 판별)

모든 경우의 수를 탐색하는 **완전 탐색(Brute Force)** 방식과 연산 횟수를 줄이는 **에라토스테네스의 체 원리**를 결합하여 풀이했습니다.

### 💡 로직 설명

1.  **3중 반복문(조합)**: `nums` 배열에서 서로 다른 3개의 인덱스 $(i, j, k)$를 선택합니다. 중복 선택을 피하기 위해 각 루프는 이전 인덱스보다 1 큰 값부터 시작합니다.
2.  **합 계산**: 선택된 세 수의 합($sum = nums[i] + nums[j] + nums[k]$)을 구합니다.
3.  **효율적 소수 판별**: 구한 합이 소수인지 확인합니다. 2부터 해당 숫자의 **제곱근($\sqrt{n}$)**까지만 나누어 떨어지는지 확인하여 시간 복잡도를 최적화합니다.
4.  **카운팅**: 소수로 판별된 경우 결과값을 1 증가시킵니다.

### 🚀 성능 분석

- **시간 복잡도**: $O(N^3 \times \sqrt{M})$
  - $N$: 배열의 길이 (최대 50) → 3개를 뽑는 조합은 $\binom{N}{3}$으로 최대 19,600가지.
  - $M$: 세 수의 합의 최댓값 (최대 3,000) → 소수 판별 시 $\sqrt{3000} \approx 54$회 연산.
  - 최악의 경우에도 약 100만 번의 연산 내외로, 제한 시간 내에 매우 여유롭게 통과합니다.

---

## 3. 핵심 포인트

### ✅ 제곱근까지만 확인하는 이유

임의의 수 $n$이 $a \times b$로 이루어져 있을 때, $a$와 $b$ 중 적어도 하나는 $\sqrt{n}$보다 작거나 같습니다. 따라서 $\sqrt{n}$까지만 확인해도 약수의 존재 여부를 완벽하게 판별할 수 있어 불필요한 반복을 줄입니다.

### ✅ 조합(Combination)의 인덱스 관리

`j = i + 1`, `k = j + 1` 설정을 통해 별도의 체크 배열(visited) 없이도 **서로 다른 3개의 수**를 중복 없이 효율적으로 뽑아낼 수 있었습니다.
