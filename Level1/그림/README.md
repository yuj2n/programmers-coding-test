# [Programmers] 삼총사 (Level 1)

## 1. 문제 설명

- 학생들의 정수 번호가 담긴 배열 `number`가 주어질 때, **서로 다른 3명의 학생**을 선택하여 번호의 **합이 0**이 되는 '삼총사' 팀을 만들 수 있는 총 경우의 수를 구하는 문제.

---

## 2. 풀이 방식: 완전 탐색 (Brute Force & Combination)

- "고정된 3개의 요소"를 선택하는 조건이므로, 가장 직관적이고 직렬적인 3중 반복문(Loop)을 활용하여 모든 조합을 확인하는 완전 탐색으로 해결함.

### 💡 알고리즘 메커니즘

1. **중복 없는 조합 제어**: 3개의 인덱스 $(i, j, k)$를 고정할 때, 이전 인덱스의 다음 위치부터 탐색을 시작하여 중복된 조합(예: `[1, 2, 3]`과 `[3, 2, 1]`)을 원천 차단함.

- `i` 범위: `0` ~ `length - 3`
- `j` 범위: `i + 1` ~ `length - 2`
- `k` 범위: `j + 1` ~ `length - 1`

2. **조건 판별**: 선택된 `number[i] + number[j] + number[k]`의 합이 `0`인 경우 카운트(`answer`)를 증가시킴.

### 💻 JavaScript 구현 코드

```javascript
function solution(number) {
  let answer = 0;
  const len = number.length;

  // 3중 반복문을 이용한 조합(Combination) 구현
  for (let i = 0; i < len - 2; i++) {
    for (let j = i + 1; j < len - 1; j++) {
      for (let k = j + 1; k < len; k++) {
        if (number[i] + number[j] + number[k] === 0) {
          answer++;
        }
      }
    }
  }

  return answer;
}
```

### 🚀 성능 분석 (Complexity)

- **시간 복잡도**: $O(N^3)$
- 주어진 배열의 길이 $N$은 최대 `13`임.
- 최악의 경우에도 조합의 수는 $\binom{13}{3} = 286$번에 불과하므로, $O(N^3)$ 알고리즘으로도 몇 밀리초(ms) 내에 매우 안정적으로 통과함.

- **공간 복잡도**: $O(1)$
- 별도의 배열이나 동적 메모리를 할당하지 않고 기본 포인터 변수와 카운터만 사용하므로 메모리를 거의 소모하지 않음.

## 3. 핵심 포인트 및 유사 문제 비교

| 비교 항목             | **삼총사**                                                                                         | **소수 만들기**                                                                                             |
| :-------------------- | :------------------------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------- |
| **공통점**            | • `j = i + 1`, `k = j + 1` 규칙을 활용한 **중복 없는 조합 탐색**<br>• 배열 내 3개 요소의 총합 계산 | • `j = i + 1`, `k = j + 1` 규칙을 활용한 **중복 없는 조합 탐색**<br>• 배열 내 3개 요소의 총합 계산          |
| **차이점: 판별 조건** | 합이 정확히 `0`인지 비교 (`sum === 0`)                                                             | 합이 **소수(Prime Number)**인지 판별 (별도 함수 필요)                                                       |
| **차이점: 최적화**    | $N \le 13$으로 매우 작아 **정확한 조합 구현**이 핵심임.                                            | $N$의 범위가 더 크고 소수 판별 연산이 겹치므로 **제곱근($\sqrt{n}$)을 활용한 소수 판별 최적화**가 필수적임. |

### 📌 회고 / Insight

- 배열의 크기($N$)가 작을 때는 복잡한 백트래킹(Backtracking)이나 재귀를 사용한 조합 알고리즘 대신, 정적 다중 루프(Multi-loop)를 사용하는 것이 가독성과 구현 속도 측면에서 훨씬 효율적임을 다시 한번 확인함.
- 인덱스 오버플로우 방지를 위해 반복문 조건을 `len - 2`, `len - 1`로 명확하게 제한하여 미세한 연산 낭비를 줄임.
