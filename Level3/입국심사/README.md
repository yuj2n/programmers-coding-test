## 1. 문제 설명

모든 사람이 심사를 받는 데 걸리는 **최소 시간**을 구하는 문제. 각 심사대마다 심사 속도가 다르며, 특정 심사대가 비어있더라도 더 빨리 끝나는 곳을 기다렸다가 갈 수 있다는 점이 핵심.

- **제한 사항**: 기다리는 사람이 최대 **10억 명**, 심사관이 최대 **10만 명**, 심사 시간은 최대 **10억 분**.
- **핵심 포인트**: 숫자의 범위가 매우 크기 때문에 일반적인 시뮬레이션으로는 절대 풀 수 없으며, **시간을 기준으로 정답을 찾아가는 이분 탐색**이 필요함!

---

## 2. 풀이 방식 (이분 탐색 / 결정 문제)

"최소 시간을 구하라"는 문제를 **"T분 안에 N명을 심사할 수 있는가?"**라는 예/아니오 문제로 바꾸어 해결(Parametric Search).

### 💡 로직 설명

1. **범위 설정**:
   - `left`: 최소 시간인 **1분**.
   - `right`: 가장 느린 심사관이 모든 사람을 처리하는 시간 **(Max Time × N)**.
2. **이분 탐색 수행**:
   - 중간값 `mid` 분 동안 **각 심사관이 최대 몇 명을 처리할 수 있는지** 합산합니다.
   - `심사 가능 인원 = Math.floor(mid / 심사관별 시간)`의 총합.
3. **범위 조정**:
   - **총합 ≥ N**: 모든 사람을 심사하기에 시간이 충분함. 일단 정답 후보(`answer`)로 저장하고, 시간을 더 줄여보기 위해 `right = mid - 1`.
   - **총합 < N**: 시간이 부족함. 시간을 더 늘려야 하므로 `left = mid + 1`.
4. **종료**: `left`가 `right`보다 커지는 순간, 저장된 `answer`가 최솟값이 됨.

```javascript
function solution(n, times) {
  // 1. 시간의 범위를 설정 (효율을 위해 정렬 후 최대 시간 계산)
  times.sort((a, b) => a - b);

  let left = 1;
  let right = times[times.length - 1] * n;
  let answer = right;

  while (left <= right) {
    let mid = Math.floor((left + right) / 2);
    let count = 0;

    // 2. mid 시간 동안 심사할 수 있는 총 인원 수 계산
    for (let time of times) {
      count += Math.floor(mid / time);
      if (count >= n) break; // 이미 n명을 넘었다면 조기 종료
    }

    // 3. 결정 문제 결과에 따라 범위 좁히기
    if (count >= n) {
      answer = mid; // 가능하다면 후보로 등록
      right = mid - 1; // 더 최솟값이 있는지 확인
    } else {
      left = mid + 1; // 불가능하다면 시간 늘리기
    }
  }

  return answer;
}
```

## 3. 시행착오 및 해결 과정

### ❌ 그리디(Greedy) 방식의 한계

- "현재 비어있는 곳 중 가장 빨리 끝나는 곳으로 사람을 보낸다"는 시뮬레이션 방식은 사람 수($N$)가 10억 명이기 때문에 **루프 횟수가 너무 많아져 시간 초과**가 발생합니다.

### ✅ 파라메트릭 서치(Parametric Search)의 적용

- 최솟값을 직접 찾는 대신, "이 시간이면 다 할 수 있어?"라고 물어보는 방식이 훨씬 빠릅니다.
- $O(N)$의 문제를 $O(M \log(\text{MaxTime} \times N))$으로 단축시켜 효율성 테스트를 완벽하게 통과할 수 있습니다. (여기서 $M$은 심사관의 수)

### ⚠️ 주의할 점

- JavaScript에서 `right` 값이 $2^{53}-1$을 초과할 정도로 커질 가능성이 있다면 `BigInt`를 고려해야 합니다. 하지만 프로그래머스 환경에서는 일반 `Number`로도 대부분 통과 가능합니다.
